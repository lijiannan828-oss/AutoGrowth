# 内存使用情况分析报告

## 分析目标

检查每个 task 的实际内存占用情况，判断 4Gi 内存分配是否合适。

## 分析方法

1. 查看 Cloud Run Job task 日志
2. 分析 exit=-9 错误的分布
3. 对比成功和失败 job 的内存使用模式
4. 检查是否有显式的内存监控日志

## 关键发现

### 1. 错误模式分析

**失败 Job (bbwz4)**:
- 490 个文件失败
- 所有失败都是 `exit=-9` (SIGKILL)
- `exit=-9` 通常表示 OOM (Out of Memory)

**成功 Job (bnk8w)**:
- 540 个文件全部成功
- 没有 exit=-9 错误

### 2. Task 失败分布

**失败模式**:
- 大部分 Task 都有失败
- 失败是随机的，不是特定 Task
- 失败发生在处理过程中，不是启动时

### 3. 并发执行影响

**时间重叠**:
- 两个 job 同时运行
- 最多 100 个任务同时运行
- 总内存需求: 400Gi

**资源竞争**:
- 两个 job 竞争资源
- 可能导致内存不足

## 内存使用分析

### 当前配置

- **每个 Task**: 4Gi 内存
- **每个 Job**: 最多 50 个并行任务
- **两个 Job 同时运行**: 最多 100 个任务
- **总内存需求**: 100 × 4Gi = 400Gi

### 实际使用情况

**从日志分析**:
1. **没有显式的内存监控日志**
   - Worker 代码中没有内存使用监控
   - 无法直接看到内存占用情况

2. **exit=-9 错误模式**
   - 所有失败都是 exit=-9
   - 这通常表示进程被 OOM Killer 终止
   - 说明内存确实不足

3. **失败时间分布**
   - 失败发生在处理过程中
   - 不是启动时失败
   - 说明在处理文件时内存不足

### 内存需求估算

**FFmpeg 处理视频时的内存需求**:
- 视频解码: 需要将视频帧加载到内存
- 字幕处理: 需要加载字幕文件
- 编码输出: 需要缓冲区
- 临时文件: 可能占用磁盘和内存

**估算**:
- 1080p 视频处理: 可能需要 2-4Gi 内存
- 4Gi 内存可能刚好够用，但在并发情况下可能不足

## 问题分析

### 1. 内存分配是否足够？

**单个 Task 处理单个文件**:
- 4Gi 内存可能足够
- 但处理大文件时可能接近上限

**并发情况**:
- 多个任务同时运行
- 系统内存压力更大
- 可能导致 OOM

### 2. 内存清理是否及时？

**当前实现**:
- 每个文件处理完后清理临时文件
- 调用 `gc.collect()`
- 但可能不够及时

**问题**:
- FFmpeg 进程可能占用大量内存
- 进程结束后内存可能不会立即释放
- 多个任务同时运行时，内存压力累积

### 3. 并发控制问题

**核心问题**:
- 两个 job 同时运行
- 100 个任务同时运行
- 总内存需求 400Gi
- 可能超出实际可用内存

**添加内存使用日志**:

```python
import psutil
import os

def log_memory_usage():
    """记录内存使用情况"""
    process = psutil.Process(os.getpid())
    memory_info = process.memory_info()
    memory_mb = memory_info.rss / 1024 / 1024
    
    logger.info(f"📊 当前内存使用: {memory_mb:.2f} MB / 4096 MB ({memory_mb/4096*100:.1f}%)")
```

## 结论

### 内存分配评估

**4Gi 内存可能刚好够用，但在并发情况下不足**:
- 单个任务处理单个文件: 4Gi 可能足够
- 多个任务同时运行: 内存压力大，可能不足
- 两个 job 同时运行: 100 个任务，总需求 400Gi，可能超出配额

### 根本问题

**不是内存分配大小的问题，而是并发控制的问题**:
- 4Gi 内存对于单个任务可能是合适的
- 但两个 job 同时运行导致资源竞争
- 需要实现并发控制，避免同时运行多个 job
