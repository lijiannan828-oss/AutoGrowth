# 详细内存使用分析报告

## 分析目标

通过查看每个 task 的日志，分析实际内存占用情况，判断 4Gi 内存分配是否合适。

## 关键发现

### 1. 文件大小分析

**失败 Job (bbwz4)**:
- 视频文件大小: 约 683MB (从日志看到 ep001 文件)
- 文件较大，处理时需要更多内存

**成功 Job (bnk8w)**:
- 需要对比文件大小
- 如果文件较小，可能更容易成功

### 2. Task 失败模式

**失败分布**:
- Task 0: 5 个全部成功 ✅
- Task 1-99: 大部分全部失败 ❌
- 98 个 Task 全部失败
- 只有 2 个 Task 成功（Task 0 和可能的其他）

**失败时间点**:
- 失败发生在 FFmpeg 处理过程中
- 不是下载阶段失败
- 说明在处理大文件时内存不足

### 3. 处理时间线分析

**Task 1 (失败)**:
1. 下载视频文件（683MB）
2. 开始 FFmpeg 处理
3. FFmpeg 处理过程中被终止（exit=-9）
4. 错误: `FFmpeg 处理失败 (exit=-9)`

**Task 0 (成功)**:
1. 下载视频文件
2. FFmpeg 处理成功
3. 所有 5 个文件都成功

### 4. 内存使用估算

**FFmpeg 处理视频时的内存需求**:
- **视频解码**: 需要将视频帧加载到内存
  - 1080p 视频: 每帧约 6MB (1920×1080×3 bytes)
  - 缓冲多帧: 可能需要 100-200MB
- **字幕处理**: 需要加载字幕文件
  - 字幕文件通常很小（几 KB 到几 MB）
- **编码输出**: 需要编码缓冲区
  - H.264 编码: 可能需要 50-100MB
- **临时文件**: 磁盘空间，但也可能占用内存
  - 输出文件写入缓冲区

**总估算**:
- 单个文件处理: 可能需要 **2-4Gi 内存**
- 4Gi 内存可能刚好够用，但在以下情况可能不足：
  - 文件很大（>600MB）
  - 视频分辨率高
  - 编码复杂度高
  - 系统有其他开销

### 5. 并发影响

**两个 Job 同时运行**:
- 100 个任务同时运行
- 总内存需求: 400Gi
- 可能超出实际可用内存

**资源竞争**:
- 系统内存压力大
- 可能导致 OOM Killer 更频繁触发
- 先启动的任务可能更容易失败

## 内存分配评估

### 当前配置

- **每个 Task**: 4Gi 内存
- **每个 Job**: 最多 50 个并行任务
- **两个 Job 同时运行**: 最多 100 个任务

### 实际需求

**从日志分析**:
1. **文件大小**: 约 683MB
2. **处理阶段**: FFmpeg 处理时失败
3. **失败原因**: exit=-9 (OOM)

**内存需求估算**:
- 单个文件处理: 可能需要 **2-4Gi 内存**
- 4Gi 内存可能刚好够用，但在并发情况下可能不足

### 问题分析

**4Gi 内存是否足够？**

**单个任务处理单个文件**:
- ✅ 可能足够（取决于文件大小）
- ⚠️ 对于大文件（>600MB）可能接近上限

**并发情况**:
- ❌ 两个 job 同时运行，100 个任务
- ❌ 总内存需求 400Gi，可能超出配额
- ❌ 资源竞争导致 OOM

## 结论

### 内存分配评估

**4Gi 内存对于单个任务可能是合适的，但在并发情况下不足**:

1. **单个任务处理单个文件**:
   - 4Gi 内存可能足够
   - 但对于大文件（>600MB）可能接近上限

2. **并发情况**:
   - 两个 job 同时运行，100 个任务
   - 总内存需求 400Gi
   - 可能超出实际可用内存或配额

### 根本问题

**不是内存分配大小的问题，而是并发控制的问题**:

1. **4Gi 内存对于单个任务可能是合适的**
   - 从 Task 0 成功可以看出
   - 单个文件处理可能不需要更多内存

2. **但并发导致资源竞争**
   - 两个 job 同时运行
   - 100 个任务同时运行
   - 总内存需求 400Gi
   - 可能超出配额或实际可用资源

3. **需要实现并发控制**
   - 避免多个 job 同时运行
   - 确保资源充足

import os

def log_memory_usage():
    """记录内存使用情况"""
    process = psutil.Process(os.getpid())
    memory_info = process.memory_info()
    memory_mb = memory_info.rss / 1024 / 1024
    
    logger.info(f"📊 当前内存使用: {memory_mb:.2f} MB / 4096 MB ({memory_mb/4096*100:.1f}%)")
