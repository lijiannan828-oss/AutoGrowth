# 协作指南：如何更默契地协作

## 核心原则

### 1. 主动检查和提醒

**我的责任**：
- ✅ 代码审查时主动检查 Firestore 查询
- ✅ 发现需要索引时立即提醒
- ✅ 提供索引创建链接和回退方案
- ✅ 使用检查清单确保不遗漏

**您的责任**（建议）：
- ✅ 编写 Firestore 查询时主动询问是否需要索引
- ✅ 代码审查时检查索引配置
- ✅ 部署前验证索引状态

### 2. 建立检查机制

**自动化检查**：
- ✅ 使用 `check_firestore_queries.py` 检查查询
- ✅ 使用 `DEVELOPMENT_CHECKLIST.md` 检查清单
- ✅ 部署前运行检查脚本

**手动检查**：
- ✅ 代码审查时使用检查清单
- ✅ 部署前验证所有检查项

### 3. 标准化沟通

**代码审查提醒模板**：
```
⚠️ **Firestore 索引检查**

这个查询需要复合索引：
- Collection: `collection_name`
- Fields: `field1` (ASC) + `field2` (DESC)

请确认：
- [ ] 索引已添加到 `firestore.indexes.json`
- [ ] 索引已部署
- [ ] 索引状态为 "Enabled"
- [ ] 有回退方案（如果索引未就绪）
```

**开发提醒模板**：
```
💡 **提醒**

您正在使用需要索引的查询模式。
请：
1. 添加索引到 `firestore.indexes.json`
2. 部署索引
3. 添加回退方案
```

## 具体工作流程

### 阶段 1: 代码编写

**当编写 Firestore 查询代码时**：

1. **识别查询模式**
   - 使用 `check_firestore_queries.py` 检查
   - 或手动检查：是否有 `order_by` + `where`？

2. **如果需要索引**：
   - 添加到 `firestore.indexes.json`
   - 添加回退方案
   - 添加注释说明

3. **提交代码前**：
   - 运行 `check_firestore_queries.py`
   - 检查 `DEVELOPMENT_CHECKLIST.md`
   - 确保所有检查项通过

### 阶段 2: 代码审查

**代码审查时**：

1. **我（AI）会**：
   - 自动检查 Firestore 查询
   - 识别需要索引的模式
   - 提醒添加索引配置
   - 提供索引创建链接

2. **您（开发者）会**：
   - 检查索引配置
   - 验证回退方案
   - 确认测试覆盖

### 阶段 3: 测试

**测试时**：

1. **功能测试**
   - 测试查询功能
   - 测试回退方案

2. **索引依赖测试**
   - 检查索引是否存在
   - 验证查询是否可用

3. **集成测试**
   - 端到端测试
   - 自动触发流程测试

### 阶段 4: 部署

**部署前**：

1. **验证检查清单**
   - 运行 `check_firestore_queries.py`
   - 检查 `DEVELOPMENT_CHECKLIST.md`
   - 确保所有检查项通过

2. **部署索引**
   - 如果新增索引，先部署索引
   - 验证索引状态

3. **部署代码**
   - 部署代码
   - 验证功能
