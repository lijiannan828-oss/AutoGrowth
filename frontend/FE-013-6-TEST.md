# FE-013-6 竞态条件修复测试指南

## 问题描述

在极端情况下（下载速度极快但 API 响应较慢），会出现竞态条件：

1. 初始批次文件（如 50 个）快速下载完成
2. 队列变空，触发 `fetchNextBatch`
3. 但 `fetchNextBatch` 有网络延迟（如 2 秒）
4. 在这 2 秒内，`pool.wait()` 检测到 `running === 0 && queue.length === 0`
5. 误判任务完成，提前退出
6. 导致新批次文件还没加入队列就结束了

## 修复方案

在主等待逻辑中加入外部状态检查：
- `!isFetchingUrls` - 确保不在获取下一批 URL
- `!hasMoreBatches` - 确保没有更多批次需要获取
- `pool.isIdle()` - 确保队列空闲且无运行任务

只有当**所有条件**都满足时，才判定任务真正完成。

## 测试步骤

### 1. 模拟快速下载 + 慢速 API

**场景**: 下载速度极快，但 API 响应慢

1. 打开浏览器开发者工具（F12）
2. 切换到 Network 标签
3. 设置网络节流为 "Fast 3G" 或 "Slow 3G"（模拟 API 延迟）
4. 开始下载大量文件（建议 500+ 个文件，分布在多个批次）
5. 观察控制台日志

**预期结果**:
- 应该看到等待日志：
```
[Download] FE-013-6: 等待中... (队列空闲但正在获取: true, 还有批次: true, 剩余路径: 300)
```
- 不应该提前显示"下载完成"
- 所有批次文件都应该被下载

### 2. 验证等待逻辑

**检查点**:
- 当队列为空但正在获取下一批时，应该继续等待
- 当队列为空且没有更多批次时，才判定完成
- 日志应该显示等待状态

**示例日志序列**:
```
[Download] FE-013-3: 初始 200 个文件已加入队列，等待处理...
[Download] FE-013-4: 还有 300 个路径待获取，将在队列低于 50 时自动获取
...
[Download] FE-013-3: 所有下载任务已完成
[Download] FE-013-4: 队列长度低于阈值，触发获取下一批 URL
[Download] FE-013-6: 等待中... (队列空闲但正在获取: true, 还有批次: true, 剩余路径: 100)
[Download] FE-013-4: 批次获取成功 - 200 个文件 (总计: 400)
[Download] FE-013-4: 已添加 200 个新文件到队列
[Download] FE-013-3: 开始下载 - file201 (队列长度: 199, 运行中: 1)
...
[Download] FE-013-6: 所有下载任务已完成 (队列空闲: true, 未获取中: true, 无更多批次: true)
```

### 3. 验证完成条件

**检查点**:
- 只有当所有条件都满足时才完成：
  - `pool.isIdle() === true`
  - `isFetchingUrls === false`
  - `hasMoreBatches === false`
- 完成日志应该显示所有条件状态

### 4. 压力测试

**场景**: 大量文件（1000+），快速下载，慢速 API

1. 准备 1000+ 个文件的下载任务
2. 设置网络节流模拟 API 延迟
3. 开始下载
4. 验证所有文件都被处理

**预期结果**:
- 所有文件都应该被下载
- 不应该出现提前完成的情况
- 等待日志应该正确显示状态

## 修复前后对比

### 修复前
```
初始 50 个文件快速下载完成
→ pool.wait() 检测到队列为空
→ 立即判定完成
→ 新批次文件还没加入队列
→ 丢失大量文件
```

### 修复后
```
初始 50 个文件快速下载完成
→ pool.wait() 检测到队列为空
→ 但检查 isFetchingUrls === true
→ 继续等待
→ 新批次文件加入队列
→ 继续下载
→ 所有文件完成
```

## 代码位置

- 修复位置：`frontend/src/context/ZipDownloadContext.tsx`（第 699-723 行）
- 关键变量：
  - `isFetchingUrls`: 是否正在获取下一批 URL
  - `hasMoreBatches`: 是否还有更多批次
  - `pool.isIdle()`: 队列是否空闲

## 故障排查

如果发现仍然提前完成：

1. **检查日志**: 确认是否看到"FE-013-6"相关日志
2. **检查条件**: 确认所有条件都正确检查
3. **检查变量**: 确认 `isFetchingUrls` 和 `hasMoreBatches` 正确更新
4. **检查时序**: 确认 `fetchNextBatch` 正确设置 `isFetchingUrls`
