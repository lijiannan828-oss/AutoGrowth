# FE-013-3 生产-消费者并发模型测试指南

## 实现说明

已实现生产-消费者并发模型（AsyncPool），替代了原来的 `Promise.all(workers)` 模式。

### 核心改进

1. **AsyncPool 实现**:
   - 维护一个待处理文件队列
   - 限制并发数为 5（可配置）
   - Worker 完成一个任务后自动提取下一个任务

2. **剧集亲和性调度**:
   - 按目录分组文件
   - 同一目录的文件获得相同优先级
   - 优先处理同一目录下的文件，最大化利用目录句柄缓存

3. **队列管理**:
   - 支持优先级排序
   - 自动处理任务完成和错误
   - 提供队列状态查询接口

### 预期效果

- **并发控制**: 严格限制在 5 个并发下载
- **缓存命中率**: 同一目录的文件连续处理，目录句柄缓存命中率提高
- **性能**: 减少目录创建开销，提高下载效率

## 测试步骤

### 1. 准备测试数据

选择一个包含多个目录和文件的剧集进行下载测试，例如：
- 一个剧集包含多个语言文件夹（en, ar, th 等）
- 每个语言文件夹包含多个集数文件（ep001.mp4, ep002.mp4 等）
- 建议选择至少 50+ 文件的目录

### 2. 开始下载

1. 打开浏览器开发者工具（F12）
2. 切换到 Console 标签
3. 在资源库页面选择要下载的目录
4. 点击"下载"按钮
5. 选择保存位置

### 3. 观察控制台日志

在下载过程中，观察控制台输出：

**初始化日志**:
```
[Download] FE-013-3: 文件分组完成 - X 个目录，Y 个文件
[Download] FE-013-3: 所有文件已加入队列，等待处理...
```

**任务开始日志**（应该显示队列状态）:
```
[Download] FE-013-3: 开始下载 - drama/lang/ep001.mp4 (队列长度: 45, 运行中: 5)
```

**任务完成日志**:
```
[Download] FE-013-3: 完成下载 - drama/lang/ep001.mp4
```

**完成日志**:
```
[Download] FE-013-3: 所有下载任务已完成
```

### 4. 验证并发控制

**检查点**:
- 观察"运行中"数量，应该始终 ≤ 5
- 当有任务完成时，"运行中"数量应该立即补充到 5（如果队列中还有任务）
- "队列长度"应该逐渐减少

**示例日志序列**:
```
[Download] FE-013-3: 开始下载 - file1 (队列长度: 49, 运行中: 1)
[Download] FE-013-3: 开始下载 - file2 (队列长度: 48, 运行中: 2)
[Download] FE-013-3: 开始下载 - file3 (队列长度: 47, 运行中: 3)
[Download] FE-013-3: 开始下载 - file4 (队列长度: 46, 运行中: 4)
[Download] FE-013-3: 开始下载 - file5 (队列长度: 45, 运行中: 5)
[Download] FE-013-3: 完成下载 - file1
[Download] FE-013-3: 开始下载 - file6 (队列长度: 44, 运行中: 5)  // 立即补充
```

### 5. 验证剧集亲和性调度

**检查点**:
- 同一目录下的文件应该连续处理（通过观察文件路径）
- 目录句柄缓存命中日志应该频繁出现

**示例日志序列**（理想情况）:
```
[Download] FE-013-3: 开始下载 - drama/en/ep001.mp4
[Download] 创建/获取目录并缓存: drama/en
[Download] FE-013-3: 开始下载 - drama/en/ep002.mp4
[Download] 缓存命中: drama/en  // 缓存命中！
[Download] FE-013-3: 开始下载 - drama/en/ep003.mp4
[Download] 缓存命中: drama/en  // 缓存命中！
```

### 6. 验证目录句柄缓存效果

**检查点**:
- 观察"创建/获取目录并缓存"日志出现的次数
- 应该等于目录数量，而不是文件数量
- "缓存命中"日志应该频繁出现

**计算方法**:
- 如果有 100 个文件分布在 10 个目录中
- "创建/获取目录并缓存"应该出现约 10 次
- "缓存命中"应该出现约 90 次

- [ ] 任务完成后立即补充新任务
- [ ] 队列长度逐渐减少
- [ ] 同一目录的文件连续处理（亲和性调度）
- [ ] 目录句柄缓存命中率提高（缓存命中日志频繁出现）
- [ ] 下载功能正常（文件正确保存）
- [ ] 所有任务最终完成

## 性能指标

### 预期改进

- **目录创建调用**: 从文件数量减少到目录数量（90%+ 减少）
- **并发控制**: 严格限制在 5 个并发，避免浏览器资源耗尽
- **缓存命中率**: 同一目录文件连续处理，缓存命中率接近 100%

### 对比测试（可选）

如果需要对比性能：
1. 临时禁用亲和性调度（随机顺序）
2. 记录目录创建调用次数
3. 启用亲和性调度
4. 再次记录目录创建调用次数
5. 对比两次的差异

## 故障排查

如果发现并发控制未生效：

1. **检查日志**: 确认是否看到"FE-013-3"相关日志
2. **检查运行中数量**: 观察"运行中"数量是否始终 ≤ 5
3. **检查队列**: 确认队列长度是否正确减少
4. **检查 AsyncPool**: 确认 `concurrency` 参数正确设置

如果发现亲和性调度未生效：

1. **检查文件分组**: 确认文件是否正确按目录分组
2. **检查优先级**: 确认同一目录的文件是否有相同优先级
3. **检查处理顺序**: 观察文件处理顺序是否符合预期
