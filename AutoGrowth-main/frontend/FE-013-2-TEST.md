# FE-013-2 UI 渲染节流测试指南

## 实现说明

已实现 UI 渲染节流功能，将下载状态与渲染状态分离，避免频繁的 React 重新渲染。

### 核心改进

1. **状态分离**: 
   - 下载状态存储在 `useRef` 中（`downloadStateRefs`）
   - Worker 线程只更新 ref，不直接调用 `setState`
   - React 状态通过定时器定期更新（500ms = 2Hz）

2. **更新频率限制**:
   - UI 更新频率限制为 2Hz（每 500ms 更新一次）
   - 无论下载速度多快，UI 更新频率保持稳定

3. **最终更新保证**:
   - 下载完成后立即执行最后一次更新
   - 确保进度条不会停留在 99%，始终更新到 100%

### 预期效果

- **UI 帧率**: 下载过程中主线程不阻塞，UI 更新频率限制在 2Hz
- **性能**: 减少 React 重新渲染次数，提高浏览器响应性
- **用户体验**: 进度条平滑移动，不会因为频繁更新而卡顿

## 测试步骤

### 1. 准备测试数据

选择一个包含大量文件的目录进行下载测试（建议 100+ 文件），这样可以明显观察到节流效果。

### 2. 开始下载

1. 打开浏览器开发者工具（F12）
2. 切换到 Console 标签
3. 切换到 Performance 标签（用于监控性能）
4. 在资源库页面选择要下载的目录
5. 点击"下载"按钮
6. 选择保存位置

### 3. 观察控制台日志

在下载过程中，观察控制台输出：

**初始化日志**:
```
[Download] FE-013-2: 下载状态 ref 已初始化
```

**更新日志**（应该每 500ms 出现一次）:
```
[Download] 正在下载 (50/100) (5.2 MB/s)
```

**完成日志**:
```
[Download] FE-013-2: 下载状态 ref 已清理
```

### 4. 验证更新频率

**方法 1: 控制台时间戳**
- 观察控制台中的状态更新日志
- 记录每次更新的时间戳
- 验证更新间隔约为 500ms（允许 ±50ms 误差）

**方法 2: Performance 监控**
- 在 Performance 标签中开始录制
- 开始下载
- 停止录制后查看 React 更新频率
- 验证更新频率约为 2Hz（每 500ms 一次）

### 5. 验证最终更新

**检查点**:
- 下载完成后，进度条应该显示 100%
- 不应该停留在 99%
- 状态消息应该显示"下载完成"

### 6. 性能对比（可选）

如果需要对比性能，可以：
1. 临时注释掉节流逻辑（恢复原来的每次文件完成都更新状态）
2. 记录下载过程中的 React 更新次数
3. 恢复节流逻辑，再次记录更新次数
4. 对比两次的更新次数差异

**预期结果**:
- 100 个文件，节流前：约 100 次状态更新
- 100 个文件，节流后：约 200 次状态更新（100 秒下载时间 ÷ 0.5 秒 = 200 次）
- 实际上，由于下载速度不同，更新次数会有所不同，但应该明显少于文件数量

## 技术细节

### 状态更新流程

1. **Worker 线程**:
   ```typescript
   // 只更新 ref，不更新 state
   state.completedFiles++;
   state.downloadedBytes += result.bytes;
   ```

2. **定时器**（每 500ms）:
   ```typescript
   // 读取 ref，更新 state
   const currentState = downloadStateRefs.current.get(taskId);
   updateTask(taskId, { ... });
   ```

3. **下载完成**:
   ```typescript
   // 停止定时器，执行最终更新
   clearInterval(updateInterval);
   updateTask(taskId, { progress: 100, ... });
   ```

## 故障排查

如果发现节流未生效：

1. **检查控制台日志**: 确认是否看到"下载状态 ref 已初始化"日志
2. **检查更新频率**: 观察状态更新日志的时间间隔
3. **检查定时器**: 确认 `setInterval` 正确设置（500ms）
4. **检查清理逻辑**: 确认下载完成后定时器被正确清理
