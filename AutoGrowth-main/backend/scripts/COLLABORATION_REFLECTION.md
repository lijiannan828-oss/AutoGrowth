# 协作反思：如何更默契地协作

## 问题回顾

### 核心问题

**开发阶段缺失的提醒**：
- ❌ 代码使用 `order_by` + `where` 时，没有提醒需要 Firestore 索引
- ❌ 测试脚本没有检查索引是否存在
- ❌ 代码审查时没有检查 Firestore 查询是否需要索引

**影响**：
- 代码部署后才发现问题
- 需要额外时间修复和重新部署
- 影响生产环境稳定性

## 为什么没有提醒？

### 1. 缺乏自动化检查机制 ⚠️ **主要原因**

**问题**：
- 代码审查时没有自动检查 Firestore 查询模式
- 没有识别需要索引的查询模式
- 依赖人工记忆和检查，容易遗漏

**改进**：
- ✅ 创建 `check_firestore_queries.py` 自动检查脚本
- ✅ 建立 `DEVELOPMENT_CHECKLIST.md` 检查清单
- ✅ 建立 `COLLABORATION_GUIDELINES.md` 协作指南

### 2. 缺乏标准化的开发流程 ⚠️ **主要原因**

**问题**：
- 没有标准化的开发流程检查清单
- 容易遗漏关键步骤（如索引创建）
- 每次开发都需要记住所有检查项

**改进**：
- ✅ 建立标准化的开发流程检查清单
- ✅ 每次代码审查时使用检查清单
- ✅ 部署前验证检查清单

### 3. 缺乏主动提醒机制 ⚠️ **次要原因**

**问题**：
- 代码审查时没有主动检查 Firestore 查询
- 没有提醒模板和规范
- 依赖开发者主动询问

**改进**：
- ✅ 建立代码审查提醒模板
- ✅ 主动检查 Firestore 查询
- ✅ 发现需要索引时立即提醒

### 4. 测试脚本不够全面 ⚠️ **次要原因**

**问题**：
- 测试脚本只测试功能，不检查依赖（索引）
- 没有验证查询是否真正可用
- 没有检查索引是否存在

**改进**：
- ✅ 测试脚本检查索引是否存在
- ✅ 测试脚本验证查询是否可用
- ✅ 添加索引依赖检查

## 沟通模板

### 代码审查提醒模板

**我发现需要索引的查询时**：

```
⚠️ **Firestore 索引检查**

这个查询需要复合索引：
- Collection: `pipeline_jobs`
- Fields: `drama_name` (ASC) + `updated_at` (DESC)

请确认：
- [ ] 索引已添加到 `firestore.indexes.json`
- [ ] 索引已部署
- [ ] 索引状态为 "Enabled"
- [ ] 有回退方案（如果索引未就绪）

索引创建链接：
https://console.firebase.google.com/project/.../firestore/indexes

索引配置示例：
```json
{
  "collectionGroup": "pipeline_jobs",
  "fields": [
    {"fieldPath": "drama_name", "order": "ASCENDING"},
    {"fieldPath": "updated_at", "order": "DESCENDING"}
  ]
}
```
```

### 开发提醒模板

**您编写 Firestore 查询时**：

```
💡 **提醒**

您正在使用需要索引的查询模式：
- 查询：`where("field1") + order_by("field2")`
- 需要索引：`field1` (ASC) + `field2` (DESC)

请：
1. 添加索引到 `firestore.indexes.json`
2. 部署索引：`firebase deploy --only firestore:indexes`
3. 添加回退方案（如果索引未就绪）

需要帮助？查看：backend/DEVELOPMENT_CHECKLIST.md
```
